# 待办提醒 · 修复工具

一个**双击就能用**的维护程序。桌面上的快捷方式 `待办提醒修复工具` 指向本目录。

程序本体在项目里(`D:\toolresources\DSHStool\TodoReminder\tools\fix\`),快捷方式在桌面。

---

## 一、怎么用

**双击桌面「待办提醒修复工具」** → 出现菜单:

```
   1) 检测连接状态与 AI 解析状态  (只读, 最常用)
   2) 完整体检报告                (只读)
   3) 手机远程连接: 诊断 / 修复 / 开关
   4) 已完成超 3 天 → 转入日志     (会改数据)
   0) 退出
```

也可以在命令行直接用(适合放进脚本/定时任务):

```bat
node tools\fix\tool.mjs check                    :: 连接 + AI 解析状态检测(只读)
node tools\fix\tool.mjs status                   :: 完整体检报告(只读, 含远程连接)
node tools\fix\tool.mjs remote                   :: 手机远程连接: 逐环节诊断
node tools\fix\tool.mjs remote repair --yes      :: 连接修复(清孤儿 + 重启入口)
node tools\fix\tool.mjs remote up                :: 开启远程访问并给出手机链接
node tools\fix\tool.mjs remote down              :: 关闭远程访问
node tools\fix\tool.mjs remote link              :: 显示手机链接
node tools\fix\tool.mjs remote link --reset      :: 换一条新链接(旧的作废)
node tools\fix\tool.mjs archive --yes            :: 已完成超 3 天 → 转入日志
node tools\fix\tool.mjs archive --yes --days 7   :: 改成「超 7 天」
```

**不加 `--yes` 就是预演**:只打印「将要改哪些条目」,一个字节都不写。

## 二、三个动作分别做什么

### 1) `check` — 检测连接与 AI 解析

按顺序检查:

| 检查项 | 说明 |
| --- | --- |
| 桌面端服务 | 8790 端口有没有在响应(没在响应 → 手机端/AI 识别全都不可用) |
| 手机端可达性 | 用 Tailscale/局域网 IP 再请求一次,模拟手机视角 |
| 数据文件 | 记录数、未完成数、重复机制条数 |
| 同步接口 | `/api/todos` 是否可用 |
| AI 配置 | 模型名、接口地址、密钥长度、节次表、纠错规则 |
| AI 接口 | `/api/ai` 是否可用、服务端配置与磁盘是否一致 |
| **手机远程连接** | 隧道有没有在跑、公网域名是否生效、手机链接是否就绪 |
| 开机自启 | 注册表里有没有自启项 / 看门狗 |

退出码:`0` = 全绿,`2` = 有异常(方便做监控)。

> ⚠ 关键认知:**桌面端就是服务器**。桌面端一关,手机端、网页端、AI 截图识别、DSH 桥接全部失效。
> 手机上说「不好用」时,先跑一次 `check`。

### 1.5) `remote` — 手机远程连接(诊断 / 修复 / 开关)

应用(待办提醒)内置了「公网隧道」能力:启动时自己拉起**入口层 + 守卫 + cloudflared**,退出时自己收干净。
本工具**复用应用里同一份实现**(`core/remote.mjs`),不另写一套。

```bat
node tools\fix\tool.mjs remote                  :: 逐环节诊断
node tools\fix\tool.mjs remote repair --yes     :: 一键修复
node tools\fix\tool.mjs remote up | down        :: 开关
node tools\fix\tool.mjs remote link [--reset]   :: 看链接 / 换链接
```

**链路(2026-09 修正后的架构)**:

```
手机 ──HTTPS──▶ Cloudflare 隧道 ──▶ 入口层 127.0.0.1:8445 ──▶ 应用 127.0.0.1:8790
                    ▲                    (core/remote-proxy.mjs: 用应用自己的连接码鉴权)
                    └── 守卫 127.0.0.1:8444 只负责"把隧道拉起来并保活"
```

> **为什么不让隧道直连守卫**(这是踩过的坑): dsh-remote 的守卫是为 DSH 的**多设备多角色**
> 场景设计的, 它有自己的凭据体系(长期链接 → cookie 会话 / 配对码 / 设备令牌), 并且会
> **明确拒绝**经隧道而来、不带它那套凭据的请求。手机一体包发的是 `x-token` 头, 守卫根本不看
> → 一律 401。而待办是**单用户单手机**, 应用自己的连接码就是唯一凭据; 所以让隧道指向
> 应用自己的入口层(它认 `x-token` 头 与 `?token=`), 守卫退到"只管隧道保活"的位置。

逐环节检查(顺序 = 链路顺序):**上游应用 → 依赖 → ~~宿主存活保护~~ → 本地守卫 → 手机入口层 →
隧道进程 → 无残留孤儿隧道 → 公网入口 → 公网可达 → 手机链接 → 鉴权边界 →
手机同步路径(经公网 + 连接码)**。每条失败都带「怎么修」。

> ⚠️ **2026-10-14**：「宿主存活保护」一项已失效 —— 宿主心跳机制按用户要求移除，
> 应用不再写存活标记，该检查只能报告补丁是否装上，无法再判定保护是否生效。

`repair` 会做的事(顺序 = 从最上游往下修, 少一环都不算修好):
**拉起桌面应用** → 清理**无主守卫** → 清理**孤儿隧道** → 清理失效隧道状态 → 重启入口 → 复诊。

> ⚠ 第一条最关键: 如果**桌面应用自己没在跑**, 远程入口再健康, 手机连上也只会 502。
> 所以修复会先把「待办提醒」拉起来(隐藏窗口), 再去修守卫与隧道。

> 安全边界:公网无凭据访问必须 **401**。本机直连守卫**免鉴权**是设计如此(桌面免配对),
> 所以鉴权探测必须从公网侧做 —— 拿本机测会误报。

### 1.6) 手机包(一体包)怎么知道该连哪里

电脑端每次同步都会把**当前公网入口地址**放进 `/api/sync` 的响应里, 手机包收到后存下来;
之后的「同步到电脑」「检查更新」都会把这条地址排在候选最前。

```
手机包候选顺序: 上次成功的地址 → 电脑端告知的公网入口 → 固定兜底(Tailscale / 热点 / 局域网)
```

> 为什么必须这样: 公网隧道的**域名每次重启都会变**, 手机不可能预先知道 —— 只能由电脑端告诉它。
> 首次或域名变化后, 在手机上点一次 ⚙ →「同步到电脑服务器」→「开始同步」即可学到新地址
> (与电脑同一 Wi-Fi 时走局域网地址也能完成这次引导; 学到之后就不需要同一网络了)。
> 手机端 ⚙ →「诊断信息」里能看到: 电脑地址 / 学到的公网入口 / 上次同步时间。
>
> 手机端也可以直接用**浏览器**打开设置页显示的那条链接(一次性, 最省事)。

### 2) `archive` — 已完成超 N 天 → 转入日志

把「已经完成、且超过 N 天没动过」的条目从主数据里移到日志,主界面就只剩最近的事项。

**自动保护三条:**

1. **重复机制条目一条都不动**(`rule` 非空的、或旧式 `repeat` 非空的)。
   它们保持「3 条未来 + 3 条历史」的滚动窗口,归档会破坏自动补条机制。
2. **最近 N 天内完成的保留**(默认 N=3)。
3. **归档前必备份**,并且**先把日志写好、再动数据**,确保不丢。

> ⚠ **归档写的是墓碑, 不是物理删除**(2026-09 修正)。原因: 同步是 LWW("最后写入者胜"),
> 而"记录 vs 什么都没有"这种情况下**记录必胜** —— 物理删掉的条目会被手机/其它设备上的
> 旧副本原样推回来(实测: 归档 62 条, 下次同步全被复活)。墓碑带**当前时间戳**,
> 在 LWW 里一定赢过任何旧副本, 跨设备才真的删得掉。
> 墓碑默认保留 90 天(`tombstoneKeepDays`), 超期的会在下次归档时顺手清掉 ——
> 留够时间是为了让所有设备都同步过一轮, 否则刚删就被别的设备复活。

执行时会**短暂停止桌面端**(约 5~10 秒),改完自动重新拉起并做健康检查 —— 因为桌面端把数据放在内存里,不停它的话改动会被内存里的旧数据覆盖。

日志位置:`tools\fix\运行\logs\`
- `完成日志.json` — 机器可读,含全部字段(可追溯/可回灌)
- `任务完成日志.md` — 人看的清单,按日期分组

> 注意区分: 这两份是**归档日志**(业务数据)。工具**自己不再为每次运行写日志文件** ——
> 那是没必要的占用。需要留档时自己重定向即可: `node tool.mjs check > out.txt`。

### 与应用共用的实现(不重复造)

| 能力 | 唯一实现在 | 谁在用 |
| --- | --- | --- |
| 远程隧道(起/停/状态/链接/诊断/修复) | `core/remote.mjs` | 应用主进程 `electron/main.js` + 本工具 `remote.mjs` |
| 守卫「宿主存活检查」补丁（**2026-10-14 已停用**） | `shots/patch-guard-host-liveness.mjs` | 原先靠宿主心跳生效；心跳已移除，补丁装上也收不到信号 |

> 为什么要给守卫打补丁:隧道是 `detached` 启动的。应用被**强制结束**(任务管理器/崩溃)时
> Electron 的 `before-quit` 不会跑 → 隧道会变成"域名还在、后端已死"的孤儿入口。
> 补丁让守卫每 10 秒看一次:①上游 `/api/health` 连续 2 次不通,或 ②宿主心跳文件过期 120 秒
> → 自己把隧道收掉再退出(实测:硬杀应用后 **15 秒**内自愈)。
> 只有设置了 `TODO_REMOTE_HOST_PID` 的实例才启用,**DSH 那套守卫行为完全不变**。
>
> ⚠️ **2026-10-14**：宿主心跳已按用户要求移除（`core/remote.mjs` 不再写 `host.heartbeat`），
> 上面的 ② 永远收不到信号 —— **孤儿隧道自愈能力随之失效**，需手动停止远程访问。
